Cas 1 — Le modèle de responsabilité partagée

Domaine 2 — Sécurité

Scénario : Une entreprise utilise trois services : une application sur EC2, une base RDS et des fonctions Lambda. Le responsable sécurité veut savoir précisément ce que son équipe doit gérer pour chacun.

Lecture du schéma, étape par étape

  1. Plus le service est managé (EC2 → RDS → Lambda), plus la zone bleue (AWS) monte.
  2. Sur EC2, c'est vous qui appliquez les correctifs de l'OS invité et installez le moteur de base de données.
  3. Sur RDS, AWS patche l'OS et le moteur ; vous gérez les données, les accès, les security groups et le chiffrement.
  4. Sur Lambda, vous ne gérez que le code, les permissions IAM et les données.
  5. Les 4 premières lignes restent toujours au client, quel que soit le service.

📝 Question type examen : Pour Amazon RDS, laquelle de ces tâches relève du client ?

Choisissez une réponse

✅ Réponse : C — AWS gère l'OS, le moteur et le matériel de RDS. Le client garde toujours ses données et ses accès.

⚠️ Piège à éviter : « Le chiffrement est fait par AWS » → faux : AWS fournit les outils (KMS, chiffrement par défaut de S3), mais choisir et configurer le chiffrement reste la responsabilité du client.

Cas 2 — L'infrastructure mondiale AWS

Domaine 1 — Concepts

Scénario : Une entreprise française lance un site de vente en ligne. Ses clients sont en France, mais elle a aussi quelques clients aux États-Unis. Les données personnelles des clients européens doivent rester dans l'UE (RGPD).

Lecture du schéma, étape par étape

  1. Choisir la Région Paris : conformité RGPD (critère n°1) + proximité des clients.
  2. Déployer l'application sur au moins 2 AZ → si un data center tombe, le site reste en ligne (haute disponibilité).
  3. Utiliser CloudFront : les images et vidéos sont mises en cache dans les Edge Locations, y compris à New York → faible latence pour les clients américains, sans déplacer la base de données hors de l'UE.
  4. Les données ne quittent jamais la Région sans action explicite du client.

📝 Question type examen : Quelle est la composition minimale d'une Région AWS ?

Choisissez une réponse

✅ Réponse : B — Chaque Région contient au minimum 3 AZ, chacune composée d'un ou plusieurs data centers.

⚠️ Piège à éviter : Une Edge Location n'est pas une AZ : on n'y lance pas d'instances EC2. Elle sert au cache (CloudFront), au DNS (Route 53) et à la protection (Shield, WAF).

Cas 3 — Application web hautement disponible (3 tiers)

Domaine 3 — Technologie

Scénario : Une entreprise héberge son site e-commerce sur un seul serveur. À chaque panne ou pic de trafic, le site tombe. Elle veut une architecture hautement disponible, élastique et tolérante aux pannes.

Lecture du schéma, étape par étape

  1. Route 53 résout le nom de domaine ; CloudFront sert les fichiers statiques depuis S3 (rapide, moins de charge sur les serveurs).
  2. L'Application Load Balancer répartit les requêtes entre les instances des deux AZ.
  3. L'Auto Scaling Group ajoute des instances lors des pics (élasticité) et remplace automatiquement une instance défaillante (tolérance aux pannes).
  4. Les serveurs sont dans des sous-réseaux privés : inaccessibles directement depuis Internet. La NAT Gateway leur permet de télécharger des mises à jour.
  5. RDS Multi-AZ : copie synchrone dans l'AZ B. Si la base principale tombe, basculement automatique vers le standby.
  6. Résultat : si toute l'AZ A tombe, le site continue de fonctionner dans l'AZ B.

📝 Question type examen : Quelle combinaison offre le plus haut niveau de disponibilité pour une application web ? (Choisissez-en deux.)

Choisissez 2 réponses

✅ Réponse : A et C — Multi-AZ pour le calcul (ELB + Auto Scaling) et pour la base de données (RDS Multi-AZ).

⚠️ Piège à éviter : Multi-AZ = disponibilité (le standby ne sert pas de lecture). Read Replica = performance en lecture. Ne les confondez pas !

Cas 4 — Application 100 % serverless

Domaine 3 — Technologie

Scénario : Une startup lance une application de réservation. Le trafic est imprévisible (0 utilisateur la nuit, des milliers le samedi). Elle n'a pas d'administrateur système et veut payer uniquement ce qu'elle consomme.

Lecture du schéma, étape par étape

  1. Le site (HTML, JS, images) est hébergé sur S3 et distribué par CloudFront.
  2. L'utilisateur se connecte via Cognito, qui lui remet un jeton.
  3. Les appels d'API passent par API Gateway (qui vérifie le jeton) et déclenchent des fonctions Lambda (max 15 min par exécution).
  4. Les données sont dans DynamoDB (mode à la demande).
  5. La nuit, aucune requête = presque aucun coût. Le samedi, tout monte en charge automatiquement.

📝 Question type examen : Quelle option nécessite le MOINS de gestion opérationnelle pour exécuter du code backend ?

Choisissez une réponse

✅ Réponse : B — Lambda est serverless : ni serveur, ni OS, ni scaling à gérer.

⚠️ Piège à éviter : Si la tâche dure plus de 15 minutes, Lambda ne convient pas → EC2, ECS/Fargate ou AWS Batch.

Cas 5 — Sécuriser le réseau : Security Group vs Network ACL

Domaine 2 — Sécurité

Scénario : Un serveur web reçoit des requêtes HTTPS. L'équipe sécurité remarque des attaques venant de l'adresse IP 203.0.113.50 et veut la bloquer.

Lecture du schéma, étape par étape

  1. Une requête entrante traverse d'abord la NACL (frontière du sous-réseau), puis le Security Group (frontière de l'instance).
  2. Security Group = avec état (stateful) : si la requête entrante sur le port 443 est autorisée, la réponse sortante est automatiquement autorisée.
  3. NACL = sans état (stateless) : il faut autoriser explicitement l'entrée et la sortie (ports éphémères 1024-65535).
  4. Un Security Group ne connaît que des règles Allow → impossible de bloquer une IP précise avec lui.
  5. Solution : ajouter dans la NACL une règle DENY pour 203.0.113.50 avec un numéro inférieur aux règles Allow (les règles sont évaluées dans l'ordre).

📝 Question type examen : Quel composant permet de refuser explicitement le trafic d'une adresse IP au niveau du sous-réseau ?

Choisissez une réponse

✅ Réponse : B — Seules les NACL supportent des règles Deny, et elles s'appliquent au sous-réseau.

⚠️ Piège à éviter : Pour bloquer une attaque applicative (injection SQL, XSS) ou filtrer par pays au niveau HTTP → AWS WAF, pas la NACL.

Cas 6 — Découpler une application : SQS et SNS

Domaine 3 — Technologie

Scénario : Lors du Black Friday, le service de traitement des commandes d'un site est saturé et les commandes sont perdues. De plus, chaque commande doit déclencher un e-mail, un SMS, la facturation et la mise à jour du stock.

Lecture du schéma, étape par étape

  1. SQS : le site dépose chaque commande dans une file. Les workers les traitent à leur rythme. Si le traitement est lent ou tombe, aucune commande n'est perdue → couplage faible.
  2. Les workers peuvent être dans un Auto Scaling Group qui grandit selon la longueur de la file.
  3. SNS : un seul message « commande créée » est publié sur un topic et poussé à tous les abonnés (e-mail, SMS, SQS, Lambda).
  4. Combinaison classique SNS + SQS (« fan-out ») : chaque service a sa propre file et traite la commande indépendamment.

📝 Question type examen : Quel service permet de découpler les composants d'une application afin qu'ils communiquent de façon asynchrone via une file de messages ?

Choisissez une réponse

✅ Réponse : B — SQS = file d'attente de messages (queue).

⚠️ Piège à éviter : Mot « file d'attente » / « découpler » → SQS. Mot « notifier » / « abonnés » / « pub/sub » → SNS. Envoyer des e-mails marketing en masse → SES.

Cas 7 — Architecture hybride et migration

Domaine 1/3 — Migration et connectivité

Scénario : Une banque veut migrer progressivement vers AWS : elle garde certains serveurs sur site, migre sa base Oracle vers Aurora, et doit transférer 500 To d'archives avec une connexion Internet de 100 Mbit/s.

Lecture du schéma, étape par étape

  1. Direct Connect : liaison privée qui ne passe pas par Internet, débit constant — idéal pour une banque. Mise en place : plusieurs semaines.
  2. Site-to-Site VPN : opérationnel en quelques heures, chiffré, via Internet. Souvent utilisé en secours de Direct Connect.
  3. SCT convertit le schéma Oracle → PostgreSQL ; DMS migre les données pendant que la base Oracle continue de fonctionner (temps d'arrêt minimal).
  4. Storage Gateway : les serveurs locaux voient un partage de fichiers classique, mais les données sont stockées dans S3.
  5. 500 To à 100 Mbit/s ≈ 460 jours ! → Snowball Edge : AWS envoie des appareils, on les remplit, on les renvoie.

📝 Question type examen : Une entreprise doit transférer 300 To vers AWS en une semaine avec une bande passante limitée. Quelle solution ?

Choisissez une réponse

✅ Réponse : C — Transfert physique hors ligne : la bande passante ne limite plus.

⚠️ Piège à éviter : Migration Oracle → Aurora (moteurs différents) = SCT + DMS. Migration MySQL → RDS MySQL (même moteur) = DMS seul suffit.

Cas 8 — Sécurité en profondeur (défense en couches)

Domaine 2 — Sécurité

Scénario : Un site public subit des attaques : tentatives d'injection SQL, pics de trafic DDoS et une instance compromise qui communique avec une adresse IP malveillante. L'entreprise veut une stratégie de sécurité complète.

Lecture du schéma, étape par étape

  1. Chaque couche bloque un type de menace : Shield (DDoS), WAF (attaques web), Security Group (ports), IAM (identités), KMS/ACM (chiffrement).
  2. GuardDuty analyse CloudTrail, VPC Flow Logs et DNS → il détecte l'instance qui communique avec une IP malveillante.
  3. Inspector trouve les logiciels vulnérables, Macie les données personnelles exposées dans S3.
  4. Security Hub rassemble toutes les alertes ; Detective aide à comprendre l'origine de l'incident.
  5. CloudTrail et Config fournissent les preuves pour l'audit.

📝 Question type examen : Quel service détecte qu'une instance EC2 communique avec une adresse IP connue pour héberger des logiciels malveillants ?

Choisissez une réponse

✅ Réponse : C — GuardDuty = détection de menaces par analyse des logs (dont VPC Flow Logs et DNS).

⚠️ Piège à éviter : Inspector analyse les vulnérabilités avant l'attaque (logiciels non patchés) ; GuardDuty détecte une activité malveillante en cours.

Cas 9 — Enquête après incident : CloudTrail, Config ou CloudWatch ?

Domaine 2/3 — Surveillance et audit

Scénario : Un vendredi après-midi, le serveur devient lent. On découvre qu'un port SSH a été ouvert à tout Internet. Le responsable demande : qui a fait la modification, quelle était la configuration avant, et quel a été l'impact ?

Lecture du schéma, étape par étape

  1. CloudTrail répond à « QUI ? » : il enregistre chaque appel d'API (utilisateur, heure, IP source, action).
  2. Config répond à « QUOI ? / est-ce CONFORME ? » : historique de la configuration de chaque ressource et évaluation par rapport à des règles.
  3. CloudWatch répond à « COMMENT ça va ? » : métriques, journaux, alarmes (qui peuvent notifier via SNS ou déclencher une action).
  4. Astuce : Config peut aussi corriger automatiquement une ressource non conforme (remédiation).

📝 Question type examen : Un auditeur veut connaître l'historique des modifications de configuration d'un bucket S3 au cours des 6 derniers mois. Quel service ?

Choisissez une réponse

✅ Réponse : B — Config enregistre l'état de la configuration au fil du temps.

⚠️ Piège à éviter : Si la question demande « quel utilisateur » ou « quel appel d'API » → CloudTrail, même si elle parle de configuration.

Cas 10 — Optimiser le stockage S3 avec le cycle de vie

Domaine 3/4 — Stockage et coûts

Scénario : Une entreprise stocke ses journaux dans S3 Standard. Ils sont consultés souvent pendant 30 jours, rarement jusqu'à 90 jours, presque jamais ensuite, et doivent être conservés 7 ans pour la réglementation. La facture S3 explose.

Lecture du schéma, étape par étape

  1. On crée une règle de cycle de vie : les objets changent automatiquement de classe selon leur âge.
  2. J0–J30 : Standard (accès fréquent). J30 : Standard-IA (moins cher, toujours disponible en millisecondes).
  3. J90 : Glacier Flexible Retrieval. J365 : Glacier Deep Archive (la classe la moins chère d'AWS).
  4. Après 7 ans : expiration → suppression automatique.
  5. Si on ne connaît pas le schéma d'accès → S3 Intelligent-Tiering fait le travail automatiquement.

📝 Question type examen : Quelle fonctionnalité S3 permet de déplacer automatiquement les objets vers une classe de stockage moins chère après un certain nombre de jours ?

Choisissez une réponse

✅ Réponse : C — Les règles de cycle de vie gèrent les transitions et l'expiration.

⚠️ Piège à éviter : One Zone-IA n'est à choisir que pour des données recréables (une seule AZ). Pour des archives réglementaires → Glacier / Deep Archive.

Cas 11 — Choisir la bonne option d'achat EC2

Domaine 4 — Tarification

Scénario : Une entreprise a 4 charges de travail : (1) une base de données qui tourne 24h/24 depuis 3 ans, (2) des calculs de rendu vidéo relançables, (3) un logiciel Oracle sous licence par cœur physique, (4) un projet de test de 3 semaines.

Lecture du schéma, étape par étape

  1. (1) Base de données 24/7 → stable et prévisible → Instances réservées (ou Savings Plans) 3 ans, paiement intégral à l'avance = remise maximale.
  2. (2) Rendu vidéo relançable → Spot : jusqu'à 90 % moins cher, mais AWS peut récupérer l'instance avec un préavis de 2 minutes.
  3. (3) Licence par cœur/socket → Dedicated Hosts (visibilité sur le matériel physique).
  4. (4) Test de 3 semaines → On-Demand : aucun engagement, ne paie que les secondes utilisées.
  5. Bonus : une entreprise qui utilise EC2 et Lambda et Fargate → Compute Savings Plans.

📝 Question type examen : Quelle option d'achat EC2 est la plus rentable pour une charge de travail stable et prévisible exécutée en continu pendant 3 ans ?

Choisissez une réponse

✅ Réponse : C — Engagement long terme sur une charge stable = remise maximale.

⚠️ Piège à éviter : Spot n'est jamais la bonne réponse pour une base de données ou une charge critique qui ne doit pas être interrompue.

Cas 12 — Gouvernance multi-comptes avec AWS Organizations

Domaine 2/4 — Gouvernance et facturation

Scénario : Un groupe a 6 comptes AWS gérés séparément, avec 6 factures. Les développeurs lancent parfois des instances très coûteuses, et la réglementation interdit de stocker des données de production hors de l'UE.

Lecture du schéma, étape par étape

  1. AWS Organizations regroupe tous les comptes sous un compte de gestion → une seule facture (facturation consolidée).
  2. Les comptes sont rangés dans des unités organisationnelles (OU).
  3. Une SCP sur l'OU Production interdit toutes les Régions hors UE — même un administrateur du compte ne peut pas passer outre.
  4. Une SCP sur l'OU Développement interdit les types d'instances coûteux.
  5. Pour créer automatiquement un tel environnement selon les bonnes pratiques → AWS Control Tower (landing zone + garde-fous).

📝 Question type examen : Quels sont DEUX avantages de la facturation consolidée d'AWS Organizations ? (Choisissez-en deux.)

Choisissez 2 réponses

✅ Réponse : A et C — La facturation consolidée est gratuite, donne une facture unique et cumule l'usage pour les remises.

⚠️ Piège à éviter : Les SCP ne s'appliquent pas au compte de gestion et ne donnent jamais de permissions : il faut toujours une politique IAM pour autoriser une action.

Cas 13 — Les 7 stratégies de migration (7 R)

Domaine 1 — Concepts

Scénario : Une entreprise possède 7 applications à migrer : un vieil outil que plus personne n'utilise, une appli mainframe trop complexe, un environnement VMware, un serveur web standard, une base MySQL, un CRM maison et une appli monolithique stratégique.

Lecture du schéma, étape par étape

  1. Outil inutilisé → Retire. Mainframe complexe → Retain (plus tard).
  2. Environnement VMware → Relocate (VMware Cloud on AWS, sans modification).
  3. Serveur web → Rehost (« lift and shift » vers EC2, avec AWS Application Migration Service).
  4. Base MySQL → Replatform (vers RDS : AWS gère les sauvegardes et les correctifs, sans changer le code).
  5. CRM maison → Repurchase (passer à un SaaS).
  6. Appli stratégique → Refactor (réécrire en microservices/serverless pour l'agilité et l'évolutivité).

📝 Question type examen : Une entreprise déplace ses applications vers Amazon EC2 sans aucune modification pour migrer rapidement. Quelle stratégie ?

Choisissez une réponse

✅ Réponse : C — Rehost = lift and shift, aucune modification.

⚠️ Piège à éviter : Replatform = petite optimisation (« lift, tinker and shift ») ; Refactor = changer l'architecture. Le mot « sans modifier le code » oriente vers Rehost ou Replatform.

Cas 14 — Maîtriser ses coûts : quel outil, à quel moment ?

Domaine 4 — Facturation

Scénario : Une PME migre vers AWS. Le directeur financier veut : connaître le coût avant la migration, être alerté si le budget de 2 000 $/mois est dépassé, comprendre ensuite les dépenses par projet, et réduire la facture.

Lecture du schéma, étape par étape

  1. Avant : AWS Pricing Calculator pour estimer le coût mensuel de l'architecture cible.
  2. Pendant : AWS Budgets avec une alerte à 80 % et 100 % de 2 000 $ (réels ou prévus) ; Cost Anomaly Detection pour les pics anormaux.
  3. Après : Cost Explorer (graphiques par service, compte, tag) et le Cost and Usage Report pour le détail le plus fin.
  4. Par projet : activer des tags de répartition des coûts (ex. Projet=Alpha).
  5. Optimiser : Trusted Advisor (ressources inutilisées), Compute Optimizer (taille des instances), Savings Plans pour les charges stables.

📝 Question type examen : Quel outil AWS faut-il utiliser pour estimer le coût d'une charge de travail avant de la déployer ?

Choisissez une réponse

✅ Réponse : C — Le Pricing Calculator est le seul outil d'estimation avant déploiement.

⚠️ Piège à éviter : Cost Explorer fait aussi des prévisions, mais à partir de vos dépenses existantes — pas pour une architecture qui n'existe pas encore.

Cas 15 — Choisir le bon plan de support

Domaine 4 — Support

Scénario : Trois clients : (1) un étudiant qui apprend AWS, (2) une startup en production qui veut pouvoir appeler AWS à 3 h du matin, (3) une grande banque qui veut un interlocuteur technique dédié et une réponse en 15 minutes pour ses systèmes critiques.

Lecture du schéma, étape par étape

  1. (1) Étudiant → Basic (gratuit) ; ou Developer s'il veut poser des questions techniques par e-mail.
  2. (2) Startup en production, 24/7 par téléphone → Business (le moins cher avec le 24/7 et tous les contrôles Trusted Advisor).
  3. (3) Banque, TAM désigné + 15 min → Enterprise.
  4. Enterprise On-Ramp : 30 min et un pool de TAM (pas un TAM désigné).
  5. IEM (Infrastructure Event Management) = accompagnement lors d'un grand événement (lancement, Black Friday).

📝 Question type examen : Quel est le plan de support le MOINS cher qui donne accès à l'ensemble des contrôles AWS Trusted Advisor ?

Choisissez une réponse

✅ Réponse : C — À partir du plan Business, tous les contrôles Trusted Advisor sont disponibles.

⚠️ Piège à éviter : « Le moins cher qui offre X » : prenez toujours le plan le plus bas qui satisfait le critère.

Cas 16 — Pipeline d'analyse de données

Domaine 3 — Analytique

Scénario : Une chaîne de magasins veut analyser en temps réel les clics de son site et les données de ses capteurs, construire un data lake, produire des tableaux de bord pour la direction et prédire les ventes.

Lecture du schéma, étape par étape

  1. Kinesis ingère les flux de données en temps réel (Data Firehose peut les écrire directement dans S3).
  2. S3 sert de data lake : stockage durable et peu coûteux de toutes les données.
  3. Glue nettoie et transforme les données (ETL) et les référence dans un catalogue.
  4. Athena : requêtes SQL ponctuelles directement sur S3, sans serveur. Redshift : entrepôt de données pour la BI intensive.
  5. QuickSight : tableaux de bord pour la direction. SageMaker AI : modèle de prévision des ventes.

📝 Question type examen : Quel service permet d'exécuter des requêtes SQL directement sur des données stockées dans Amazon S3 sans gérer d'infrastructure ?

Choisissez une réponse

✅ Réponse : C — Athena est serverless et lit les données directement dans S3.

⚠️ Piège à éviter : Big data Hadoop/Spark → EMR. Recherche et analyse de journaux → OpenSearch. Kafka → MSK.

Cas 17 — Reprise après sinistre multi-Régions

Domaine 1/3 — Fiabilité

Scénario : Une plateforme de paiement doit rester disponible même si une Région AWS entière devient indisponible (catastrophe naturelle).

Lecture du schéma, étape par étape

  1. La Région de Paris sert tout le trafic. Francfort contient une copie réduite de l'environnement (stratégie « pilot light » / « warm standby »).
  2. La base est répliquée de façon asynchrone vers Francfort (réplica en lecture inter-Régions ; S3 peut utiliser la Cross-Region Replication).
  3. Route 53 surveille Paris avec des contrôles de santé. En cas d'échec, la politique de basculement (failover) envoie les utilisateurs vers Francfort.
  4. Le réplica est promu en base principale et l'Auto Scaling augmente la capacité.
  5. AWS Elastic Disaster Recovery et AWS Backup facilitent ce type d'architecture.

📝 Question type examen : Quelle politique de routage Amazon Route 53 dirige le trafic vers une ressource de secours lorsque la ressource principale est défaillante ?

Choisissez une réponse

✅ Réponse : C — Le routage failover s'appuie sur les contrôles de santé.

⚠️ Piège à éviter : Multi-AZ protège contre la panne d'un data center ; multi-Régions protège contre la panne d'une Région entière (et réduit la latence mondiale).
